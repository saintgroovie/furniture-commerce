# Свод правил: русский UX/UI копирайтинг

Синтез открытых редполитик (Контур, Ozon, UPROCK, практики Госуслуг) + overlays Woodright.
Это **reference** для skill `ru-ux-ui-copywriting`. В работе сначала `SKILL.md`.

## 1. Цель текста

UX-текст не «красивый абзац», а часть интерфейса. Он:

- объясняет, что делать и куда идти
- снижает тревогу в ошибках и ожидании
- держит единый голос бренда
- сканируется, а не читается как статья

Достаточно: просто / коротко / полезно. Не цель - набрать 10/10 в Главред любой ценой.

## 2. Тон (Woodright)

- Спокойный, уверенный, без пафоса и сюсюканья
- Активный залог, настоящее время
- Сначала смысл, потом смягчение (если нужно)
- Один экран - один главный смысл
- Обращение на «вы» без заискивания

## 3. Синтаксис интерфейса (Ozon)

Интерфейс = диалог. Приложение говорит текстом, пользователь отвечает кнопкой.

### Правило связанности

Заголовок + кнопка должны быть понятны **без** подзаголовка.

```text
✅ Заголовок: Заявка отправлена
   Кнопка: Перейти в каталог

❌ Заголовок: Готово!
   Кнопка: Далее
```

Допустимо (и правильно) повторять одно слово в заголовке и кнопке. Синонимы для одного действия - запрещены.

### Кнопки

| Тип | Форма | Примеры |
|-----|-------|---------|
| Действие | инфинитив | Добавить в корзину, Отправить заявку, Сбросить фильтры |
| Ознакомление | наречие | Понятно, Хорошо |
| Навигация | куда/что | В каталог, На главную, В корзину |

Не ставить `?` и `.` на кнопках. Не писать «Нажмите, чтобы…».

## 4. Заголовки и подзаголовки

- Заголовок = то, что пользователь должен понять, если прочитает только его
- Подзаголовок / lead / caption = отдельная единица смысла (не обрубок фразы заголовка)
- Разные сообщения - разные первые слова (чтобы отличать бегло)
- Без приветствий в заголовке модалки/ошибки

Структура модалки/алерта (Контур):

1. Что случилось
2. Что сделать сейчас
3. (опционально) как избежать в будущем

## 5. Пунктуация (UPROCK + Контур + Woodright)

| Знак | В UI |
|------|------|
| `.` | Только между предложениями на одной строке. Не в конце одиночной фразы, кнопки, label, chip, status |
| `,` | В полных предложениях. В коротких микротекстах чаще лучше перенос строки |
| `:` | Пара «категория - значение» или перед списком. Не армия двоеточий в профиле - лучше layout |
| `…` | Только процесс: Загружаем…, Отправляем… |
| `;` | Не использовать в UI |
| `!` | Редко; никогда в ошибках; не больше одного |
| `?` | Только реальный вопрос (подтверждение). Не на CTA |
| `—` / `–` | **Woodright: запрещены**. Только ` - ` с пробелами |

### Отбивки вместо точек

Две мысли → две строки или два блока (`lead` + `supporting`), не «А. Б.» в одном абзаце, если можно разнести.

## 6. Переносы и типографика RU

- Перенос по смыслу, не «как влезло»
- Не оставлять в конце строки короткие предлоги/союзы: в, на, с, к, о, у, и, а, но, по, из, за, от, до, для, при, без, под, не…
- **Устойчивые словосочетания не рвать** (ни CSS-wrap, ни `string[]`):
  - `мебель под проект` / `по проекту` / `под ключ`
  - `ручная отделка` / `ручная роспись` / `массив дерева`
- Плохо (hero / лид):

```text
❌ Готовые предметы, детские коллекции и мебель
   под проект
   в спокойной классике из массива

✅ Готовые предметы, детские коллекции и мебель под проект
   в спокойной классике из массива

❌ (footer, узкая колонка)
   Мебель из массива для взрослых
   и детских комнат
   Готовые модели, комнаты целиком
   и работа по проекту

✅ (смысловая отбивка + nbsp)
   Мебель из массива
   для взрослых и детских комнат
   Готовые модели, комнаты целиком и работа по проекту
```

- В Woodright: `formatRuInline` / `CopyLines` - nbsp после коротких слов, склейка `X и Y`, collocations в `format-ru-copy.ts`
- Союз `и` / `а` / `или` между словами не должен начинать следующую визуальную строку
- Числа и валюта: неразрывный пробел перед `₽` где уже принято в коде
- Новую collocation, если ломается в UI - добавить в `KEEP_TOGETHER_PHRASES` / project-pattern в `format-ru-copy.ts`

## 7. Списки

- Порядок важен → нумерованный
- Иначе → маркированный
- Пункты без `;` в конце
- Однотипные конструкции
- Фрагменты без конечной точки; пункты UI-списка - с заглавной
- Маркеры списка: спокойная точка/disc в CSS, **не** `—` / `–` / `-` как псевдобуллет
- Если пункты - полные предложения, точка только между предложениями внутри пункта

## 8. Форматы

### Empty state

- Короткий title без точки
- Body: что можно сделать дальше (1-2 строки / отбивка)
- CTA на выход из тупика

### Error / fail

- Без вины («вы неправильно»)
- Что сломалось + что сделать
- Primary = исправить/повторить; Secondary = уйти в безопасное место

### Success

- Спокойно, без «Ура!!!»
- Следующий шаг ясен

### Forms

- Label ясный; placeholder = пример, не дубль label
- Валидация: конкретно («Оставьте телефон»), не «Неверно»
- Consent - коротко; юридическое - без UI-пафоса

### Toast / snackbar

- Одна мысль, успеть прочитать
- Без длинных абзацев

### SEO title/description

- Можно обычные предложения
- UI-слой строже SEO; не ломать meta ради микроправил точек, если это вредит сниппету

## 8.1 Термины Woodright (консистентность)

Держать одни и те же слова:

- Каталог / Комнаты / Детская / По проекту / О бренде
- Добавить в корзину / Запросить расчёт / Оформить заказ
- Готовые / С выбором исполнения / По проекту
- Шоурум: Москва

Не плодить синонимы в CTA и nav.

## 9. Антипримеры

```text
❌ Упс! Что-то пошло не так.
✅ Не удалось загрузить каталог

❌ Сохранить.
✅ Сохранить

❌ Начните с заявки — остальное подскажем.
✅ Начните с заявки
   Остальное подскажем
   (или: Начните с заявки - остальное подскажем)

❌ Отправить в корзину  (если везде «Добавить в корзину»)
✅ Добавить в корзину
```
