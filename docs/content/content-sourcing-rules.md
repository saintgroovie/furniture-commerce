# Content Sourcing Rules

Правила использования внешних источников контента для Woodright storefront.

---

## Architectural constraints (неизменяемые)

- Backend — единственный source of truth для business logic
- Storefront — тонкий клиент, без бизнес-логики
- Архитектура не меняется без явного согласования
- Контент не влияет на purchase logic, cart rules, product type logic

---

## Источники и их приоритет

| Приоритет | Источник | Назначение |
|-----------|----------|------------|
| 1 (highest) | Price workbook | Цены, размеры, артикулы, структура ассортимента |
| 2 | Legacy website (woodright.ru) | Логотип, изображения, naming references, ассортиментный контекст |
| 3 | Yandex Disk | Интерьерные фото, lifestyle imagery, каталоги в PDF |

---

## Источник 1: Price Workbook

Файл: `Розничный прайс 18.03.2026.xlsx`

### Что берём

- Розничные цены (ЦЕНА МАССИВ, ЦЕНА ЛДСП, категории росписи)
- Габариты (В × Ш × Гл)
- Артикулы / коды SKU
- Структура коллекций (листы = коллекции)
- Список предметов (НАИМЕНОВАНИЕ)
- Аксессуары, детали, спецзаказы — как отдельные категории
- Количество ценовых вариантов (материал, тон)

### Что НЕ берём

- СУММА-столбцы (расчётные, зависят от КОЛ-ВО)
- Формулы и заметки для внутренних расчётов
- Наценку 15% как отдельный tier — она вычислима из базовой цены

### Правила

- Цена из workbook имеет абсолютный приоритет над ценой с legacy-сайта
- Размеры из workbook имеют приоритет над любым другим источником
- Если артикул есть в workbook, но отсутствует на сайте — артикул валиден
- Если артикул есть на сайте, но нет в workbook — требует ручной проверки

## Источник 2: Legacy Website (woodright.ru)

### Что берём

- Логотип и брендинг
- Изображения товаров (product photography)
- Интерьерные фото с карточек товаров
- Naming references: названия коллекций, категорий, комнат
- Структура каталога как ориентир (категории «Предметы», «Коллекции», «Комнаты»)
- Визуальный контекст ассортимента

### Что НЕ берём

- Цены — могут быть устаревшими
- Размеры / технические характеристики — если не подтверждены workbook
- Фильтры и атрибуты — структура может не совпадать с актуальным ассортиментом
- Business logic (корзина, checkout, типы товаров)
- UI-паттерны — текущий storefront имеет собственный design system
- Описания товаров — без верификации считаются approximate

### Правила

- Legacy site = visual/content donor, не commercial source of truth
- Если legacy цена ≠ workbook цена → доверять workbook
- Если legacy размер ≠ workbook размер → доверять workbook
- Если legacy показывает товар, отсутствующий в workbook → товар требует ручной проверки (возможно снят с производства)
- Не копировать UI-паттерны legacy site в текущий storefront

## Источник 3: Yandex Disk

URL: `https://disk.yandex.ru/d/MgKkDh5ZLXXfow`

### Что берём

- Интерьерные / lifestyle фотографии
- Каталоги коллекций в PDF (папка «Каталоги» — 31 PDF)
- Фронтальные фото товаров (папка «Front»)
- Фото фурнитуры (папка «Фурнитура»)
- Карту цветов по коллекциям (файл в папке «Front»)

### Что НЕ берём

- Цены из старых прайсов в папке «Прайс + остатки список» — могут быть устаревшими
- Остатки на складе — не актуальны для storefront
- Внутренние документы (гос.заказы, дисконт-списки)

### Правила

- Treat as asset source, not data source
- Имена папок ≠ финальная таксономия storefront без валидации
- PDF-каталоги могут содержать устаревшие цены — использовать только для визуала и названий
- Приоритет загрузки: Каталоги PDF → Front images → Контент/Размеры

## Conflict Resolution

| Конфликт | Решение |
|----------|---------|
| Цена workbook ≠ цена legacy site | Workbook wins |
| Размер workbook ≠ размер legacy site | Workbook wins |
| Товар есть в workbook, нет на legacy site | Товар валиден, нужны фото |
| Товар есть на legacy site, нет в workbook | Ручная проверка — возможно снят |
| Название отличается между источниками | Workbook name = canonical; legacy name = reference/alias |
| Фото есть на Yandex Disk, нет на legacy | Использовать Yandex Disk |
| Фото нет нигде | Пометить как missing, placeholder в storefront |

---

## Explicit Rules

1. **Цены и размеры — только из workbook.** Никаких исключений.
2. **Legacy UI patterns не копируются** в текущий storefront. Storefront имеет собственный design system.
3. **Verified vs assumed:** каждый элемент данных маркируется как verified (подтверждён workbook) или assumed (взят из secondary source, требует подтверждения).
4. **No business logic extraction.** Ни один источник контента не влияет на product_type, cart rules, checkout flow.
5. **Incremental adoption.** Сначала verified data, потом — assumed data после review.
