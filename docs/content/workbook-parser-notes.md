# Workbook Parser Notes

Документация для `scripts/parse-workbook.py`.

---

## Назначение

Скрипт читает `Розничный прайс 18.03.2026.xlsx` и преобразует каждый лист в нормализованный JSON.
Это **data preparation step** — он не модифицирует backend, storefront или seed data.

---

## Запуск

```bash
python3 scripts/parse-workbook.py                              # default path
python3 scripts/parse-workbook.py /path/to/workbook.xlsx       # custom path
```

Default path: `~/Downloads/Розничный прайс 18.03.2026.xlsx`

Dependency: `openpyxl` (`pip3 install openpyxl`)

---

## Output Files

| File | Description |
|------|-------------|
| `data/raw/workbook/parsed-sheets.json` | All parsed rows (444 items) |
| `data/raw/workbook/parse-summary.json` | Per-sheet statistics |
| `data/raw/workbook/parse-warnings.json` | Only rows with parse issues (50 items) |

---

## Architecture Safety

Этот шаг безопасен и не меняет архитектуру потому что:

1. **Не модифицирует backend** — никакие файлы в `apps/backend/` не затронуты
2. **Не модифицирует storefront** — никакие файлы в `apps/storefront/` не затронуты
3. **Не обновляет seed.ts** — данные только экспортируются в JSON
4. **Не содержит business logic** — парсер извлекает данные, не интерпретирует бизнес-правила
5. **Idempotent** — повторный запуск перезаписывает output, не накапливает state
6. **Read-only к workbook** — файл xlsx читается, не модифицируется

## Per-Sheet Configuration

Каждый лист имеет собственную конфигурацию (`SHEET_CONFIG`):

| Параметр | Назначение |
|----------|-----------|
| `code_col` | Номер столбца с артикулом |
| `name_col` | Номер столбца с наименованием |
| `qty_col` | Номер столбца с количеством (всегда 0 — заказная форма) |
| `dims_col` | Номер столбца с габаритами |
| `data_start` | Первая строка данных (после заголовков) |
| `prices` | Список price-колонок: (номер, label, тип) |

Конфигурация определена на основе ручного аудита (`docs/reports/price-workbook-audit.md`).

## Normalization Rules

### Артикулы (`product_code_normalized`)

- **Если артикул уже содержит буквенный префикс** (GR-09-1, PR-55-2, MNm-55-1) → сохраняется как есть
- **Если артикул — числовой код** (55-2, 84-2) → добавляется коллекционный префикс: `{PREFIX}-{code}`
- **Листы «Детали» и «Спецзаказ»** → артикулы не нормализуются (уже содержат собственные префиксы)
- **Prefix mapping:**
  - ОЛИВЕР → OL, ГРИНВИЧ → GR, ВВ → WW, ОКСФОРД → OX
  - ПРОВАНС → PV, ПРИНЦЕССА РОЗА → PR, КАНТРИ → CO, МОНЧЕЛСИ → MN, Аксессуары → A

### Категории (`category_normalized`)

- Определяются из наименования товара с помощью regex-паттернов
- Порядок паттернов важен: `комплекс` проверяется раньше `стол`, чтобы «Комплекс Оксфорд» не попал в «Столы»
- **36 паттернов** покрывают все типы предметов
- **Parse rate:** 444/444 (100%)

### Габариты (`dimensions_normalized`)

- Несколько regex-паттернов обрабатывают разные форматы:
  - `В.1000 х Ш.650 х Гл.30` (стандартный)
  - `В.1000 х Ш.650 х Дл.2010` (длина вместо глубины)
  - `В1529_Ш1862_Гл2146` (underscore-разделитель)
  - `500*395*440` (звёздочка-разделитель)
  - `Ш.398хГл.540хВ.18` (нестандартный порядок осей)
  - `В.1670.Ш.650.Гл.391` (точка-разделитель)
  - Slash-диапазоны: `В.750/1150` → берётся первое значение
- **Output:** `{ height_mm, width_mm, depth_mm }`
- **Parse rate (collection products):** 329/334 (98.5%)

### Цены

- Каждая ценовая колонка сохраняется в `price_variants[]`
- `price_raw` — исходное значение из ячейки
- `price_normalized` — float или null
- `price_type`:
  - `base` — базовая цена (массив, ЛДСП, тон)
  - `tier` — ценовой tier (росписи ВВ, наценка черного)
  - `modifier` — множитель (0.7–1.4, для Спецзаказа)
  - `absolute` — фиксированная цена Спецзаказа (>10)
  - `zero` — нулевая цена
  - `unknown` — не удалось классифицировать
- **Lead price** (`price_raw`, `price_normalized`, `price_type`) — первая ненулевая цена в строке

### Коллекции

- `collection_name_raw` = имя листа
- `collection_name_normalized` = slug (например, `oliver`, `willie-winkie`, `monchelsea`)

## Ambiguities Requiring Manual Review

### 1. Нулевая ЛДСП-цена

Когда `price_normalized = 0` для ЛДСП-варианта — это означает «ЛДСП-вариант недоступен»
или «цена не указана»? Парсер сохраняет `0` как есть, **не интерпретируя**.

### 2. ВВ painting tiers

Workbook хранит 4 ценовых tier-а, каждый покрывает несколько росписей.
Парсер НЕ разворачивает tier-ы в отдельные варианты по росписям.
Это бизнес-решение для следующего этапа.

### 3. Спецзаказ multiplier

Multiplier-строки (price < 10, например 1.1, 0.95) — это коэффициенты к базовой цене.
Парсер маркирует их как `price_type: "modifier"`, но НЕ вычисляет финальную цену.

### 4. Оксфорд «Мой замок»

На листе ОКСФОРД есть предметы с префиксом `MC-` (Мой замок) и `S-OX-` (навесная полка).
Парсер сохраняет их на листе ОКСФОРД, но это могут быть отдельные под-коллекции.

### 5. Мончелси — строки без артикула

Последние 4 строки (Этажерка большая, Этажерка малая и др.) не имеют артикула.
Помечены `missing_article` warning.

### 6. Аудитория коллекций (kids / adult)

Парсер НЕ определяет аудиторию. Это бизнес-решение.

### 7. Категория «Комплексы» vs «Столы» для Оксфорда

Комплексы Оксфорд включают столешницу и кровать-чердак. Парсер категоризирует их
как `complex`, но в каталоге они могут отображаться иначе.

## Limitations

1. Скрипт не скачивает и не обрабатывает изображения
2. Скрипт не маппит данные на legacy site или Yandex Disk
3. Скрипт не определяет product_type (STANDARD / CONFIGURABLE / BESPOKE)
4. Скрипт не создаёт Medusa entities
5. Скрипт зависит от ручной конфигурации `SHEET_CONFIG` — при изменении структуры workbook конфигурация обновляется вручную
