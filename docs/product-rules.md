# Product Rules

Правила по типам товаров и поведению корзины/checkout. Источник: MASTER_PRD.md.

---

## Product rules matrix

| product_type  | В корзину | Bespoke CTA | Checkout |
|---------------|-----------|-------------|----------|
| STANDARD      | да        | нет         | да       |
| CONFIGURABLE  | да        | да          | да       |
| BESPOKE       | нет       | да          | нет      |

- **STANDARD:** только «Добавить в корзину»; checkout как обычно.
- **CONFIGURABLE:** «Добавить в корзину» и «Сделать по моим размерам»; при добавлении в корзину — checkout; при выборе кастома — заявка (BespokeRequest).
- **BESPOKE:** только «Получить расчёт»; в корзину не добавляется; checkout недоступен для этого товара.

На бэкенде при добавлении в корзину проверять product_type; при попытке добавить BESPOKE возвращать 4xx и понятное сообщение.

---

## CONFIGURABLE: пресеты vs нестандарт

- **Стандартные пресеты** (варианты из каталога: размер 120/140, материал дуб/орех и т.д.) — можно покупать через корзину. Выбранный вариант добавляется как line item.
- **Нестандартные размеры или сложные изменения** (размер не из списка, комбинации не из вариантов, «под мои размеры») — не ведут в корзину; создаётся **BespokeRequest**. CTA на карточке: «Сделать по моим размерам» → форма заявки.

Итог: конфигурируемый товар с выбором из вариантов → корзина; запрос «под себя» → заявка на расчёт.

## Room Set

- Отображается как отдельная сущность; CTA: «Купить комплект», «Адаптировать под мою комнату».
- «Купить комплект»: в корзину добавляются только товары с типами STANDARD и CONFIGURABLE (по правилам выше). BESPOKE-позиции комплекта в корзину не попадают; при необходимости — отдельно заявка.
- «Адаптировать под мою комнату»: создаётся заявка (Lead + BespokeRequest с привязкой к room_set_id), весь комплект рассматривается как один запрос на расчёт.
