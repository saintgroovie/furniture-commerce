# Правила интерпретации каталога Woodright

Зафиксированные бизнес-правила для структуры коллекций, карточек, группировки и PDP. Источник коммерческих данных — workbook (parsed / normalized ingestion), не legacy-сайт.

Связанные документы: `docs/guidelines/development-rules.md`, `docs/architecture/architecture-guardrails.md`, `docs/content/content-sourcing-rules.md`, `docs/reports/price-workbook-audit.md`, `docs/storefront/storefront-content-model.md`.

---

## 1. Активные коллекции

**В scope сейчас только:**

- Oliver
- Greenwich
- Willie Winkie
- Monchelsea

**Не развивать до отдельного решения:**

- Princess Rose
- Country / London / Paris (лист workbook «КАНТРИ-ЛОНДОН-ПАРИЖ»)

Иные листы workbook (например Oxford, Provence) в публичный каталог не включаются, пока коллекция не переведена в активный набор.

---

## 2. Структура коллекций

- **Oliver** — смешанная коллекция в источнике, в каталоге моделируется как две ветки:
  - взрослый Oliver
  - детский Oliver  
  Между ветками обязательны взаимные перекрёстные ссылки (навигация «смотрите также»).

- **Willie Winkie** — только детская линейка.

- **Картины Willie Winkie** — отдельные **подколлекции** (отдельные обзорные уровни / навигация), а не обобщённые color/finish-варианты одной карточки. Иначе детский каталог визуально «пустеет».

---

## 3. Карточка товара и группировка

- **Кровати:** различаются только размером → одна **display group** (одна карточка в листинге, несколько SKU на PDP и в ссылках-соседях).
- **Кровати:** разный дизайн изголовья → **отдельные карточки**.
- **Тумбы / комоды и т.п.:** реально разная форма → отдельные карточки.
- **Банкетки / диваны** малая/большая → отдельные карточки + явные ссылки на соседние варианты (тот же смысл, другой масштаб).
- **Диваны** малая/большая → отдельные карточки + ссылки на соседей.
- Логика групп и «соседей» **только внутри одной коллекции** — не сливать товары между коллекциями.

---

## 4. Именование

- Имена уровня **Base**, **Cloud**, **Frame** и аналоги — полноценные **display names**, не «бесцветные» хвосты к заголовку.
- **Workbook / canonical** имя остаётся слоем идентичности для ingestion и маппинга; не сжимать всё в одну строку заголовка.
- Использовать **структурированную иерархию отображения**: коллекция → (опц. подколлекция) → display name → артикул / размеры / цена.

---

## 5. Обязательные поля карточки (листинг)

Каждая карточка в каталоге должна показывать:

- коллекция (человекочитаемый label)
- display name (title)
- артикул (SKU / код из workbook)
- габариты (если есть в данных workbook)
- цена (для группы — «от …» по минимальной цене среди членов группы)

---

## 6. Обязательные и желательные поля PDP

PDP должен показывать всё релевантное из данных:

- коллекция
- display name
- canonical / workbook name — если полезно отличить от display title
- артикул
- габариты
- цена
- галерея (все доступные изображения с сохранением приоритета источников)
- соседние варианты / связанные опции (размеры группы, малая/большая и т.д.)
- контекст ветки adult/children для Oliver — когда задано в метаданных

---

## 7. Приоритет изображений

1. Белый фон (disk / подготовленные ассеты)
2. Проверенные legacy
3. PDF fallback  

Не заменять более качественный источник более слабым.

---

## 8. Ограничения (инварианты)

- Не использовать legacy как источник цен и габаритов.
- Не превращать отдельные картины Willie Winkie в абстрактные «цветовые» опции одного продукта.
- Не сливать несколько backend products в один SKU без явной модели.
- Избегать хардкода «только Greenwich» в коде; предпочитать **метаданные продукта** и нормализованные поля ingestion.
- Backend — источник истины; storefront не дублирует бизнес-правила (корзина, типы товаров и т.д.).

---

## 9. Метаданные продукта (контракт отображения)

Рекомендуемые поля в `product.metadata` (заполняются seed / ingestion, читает витрина):

| Поле | Назначение |
|------|------------|
| `collection` | Slug коллекции для scope и группировки (`greenwich`, `oliver-adult`, …) |
| `collection_label` | Публичный label коллекции на карточке |
| `canonical_name` | Имя из workbook / канонический слой для PDP |
| `dimensions` | `{ width_mm, depth_mm, height_mm }` |
| `display_group` | Ключ группы (например кровати одной модели, разные размеры) |
| `display_group_title` | Общий display title для карточки группы |
| `display_group_sort` | Порядок размеров в группе |
| `subcollection_label` | Опционально: подколлекция (например линия картин WW) |
| `workbook_row_key` | Ключ строки workbook (аудит; у GR-09-1 зеркало/кровать могут делить код — см. `workbook_row_index`) |
| `workbook_row_index` | Индекс строки в листе — однозначность при коллизии кода |
| `product_code_normalized` | Нормализованный код из workbook (рядом с variant SKU) |

Перекрёстные ссылки Oliver adult/kids — задаются отдельными полями, когда появятся в данных (см. отчёт о пробелах).
