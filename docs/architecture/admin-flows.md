# Admin Flows

Поведение админки. Админка = Medusa Admin + кастомные расширения внутри backend. Отдельного приложения apps/admin нет.

Источник: MASTER_PRD.md.

---

## Разделы админки

- Products (в т.ч. product_type, варианты, опции)
- Categories
- Room Sets (CRUD, привязка продуктов)
- Orders
- Leads (список, детали, контакты)
- Bespoke Requests (список, детали, статусы, привязка к Lead)
- Payment Links (создание, список, статус)

---

## Lead и BespokeRequest

- **Lead** — контакт/источник: кто написал, откуда заявка (bespoke, room_adapt, contact). Один Lead может иметь несколько заявок на расчёт.
- **BespokeRequest** — конкретный запрос на расчёт: привязан к lead_id; опционально к product_id или room_set_id; поля запроса (размеры, материалы, бюджет, комментарий). Статусы: новая → связались → расчёт отправлен → оплачено → в производстве → завершено.

В админке: список Leads, при открытии Lead — список его BespokeRequest; список BespokeRequests с фильтром по статусу и Lead.

---

## Статусы заявок (BespokeRequest)

- новая
- связались
- расчёт отправлен
- оплачено
- в производстве
- завершено

Смена статуса — через форму/кнопки в детали заявки.

---

## Payment Link (MVP — ручной режим)

1. Админ создаёт Payment Link: выбирает сущность (заказ или lead), вводит сумму, назначение (предоплата и т.д.). Система сохраняет запись; URL либо генерируется интеграцией, либо вставляется вручную (в зависимости от реализации).
2. Админ копирует ссылку и отправляет клиенту (email, мессенджер) по шаблону из MASTER_PRD.
3. После оплаты клиентом админ вручную меняет статус Payment Link (например на «оплачено») и при необходимости статус заказа или BespokeRequest.

Webhook и автоматическое обновление статусов в первом этапе не обязательны.

---

## Шаблон сообщения клиенту (Payment Link)

```
Здравствуйте, {имя}

По вашему заказу {товар}

Предоплата: {сумма}

Ссылка на оплату:
{url}
```

Поля подставляются из контекста (Lead/Order/BespokeRequest).
