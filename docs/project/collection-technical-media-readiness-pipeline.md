# Collection technical/media readiness pipeline

## Scope

This pipeline standardizes collection readiness checks across all collections and avoids one-off ad hoc passes.

- Backend data and Store API remain the source of truth.
- Storefront remains a thin client; no business-logic migration to frontend.
- Oliver stays closed on the validated reference stack and is used as a validated reference flow, not reopened by default.

## Readiness criteria (reusable)

For each collection, evaluate these criteria in order:

1. **Metadata contract**
   - Required fields in storefront-facing `product.metadata`:
     - `collection`
     - `collection_label`
     - `canonical_name`
     - `dimensions`
   - Additional fields are optional unless actively used by storefront rendering (e.g. `display_group` for grouped cards).

2. **Media delivery**
   - Product `thumbnail` and `images[].url` resolve to store-accessible URLs.
   - No legacy `/uploads/...` URLs in storefront-facing product payloads where `/static/...` is expected by current delivery model.

3. **Storefront media correctness**
   - PDP hero and gallery use the same source ordering assumptions.
   - Open Graph image uses the same primary-image selection logic.
   - No-photo / fallback semantics are explicit and consistent.

4. **Image-order consistency**
   - Verify whether storefront assumptions require `thumbnail === images[0]`.
   - If yes for the collection flow, explicitly audit and sync drifted SKUs.

5. **Catalog/storefront scope correctness**
   - Collection appears only where intended (`/catalog`, `/kids/catalog`, bespoke flows).
   - Demo canonical seed products do not leak into real collection flows.

## Minimal reusable framework (Layer A)

### A1. Sources of truth per stage

- **Data baseline:** `data/normalized/seed-products.fixed2.json` (`medusa_collection_handle`, canonical fields, media URLs).
- **Catalog scope rules:** `apps/storefront/src/lib/catalog-scope.ts`.
- **Storefront metadata/media usage:** `apps/storefront/src/lib/product-metadata.ts`, `apps/storefront/src/components/product-card.tsx`, `apps/storefront/src/app/product/[id]/page.tsx`.
- **Per-collection closure docs:** under `docs/project/` and `docs/collections/<collection>/`.

### A2. Reusable statuses

Use exactly these status buckets:

- `OK`
- `needs metadata fix`
- `needs media delivery fix`
- `needs storefront correctness fix`
- `needs image-order sync`
- `needs manual review`

### A3. Reusable execution checklist

For each collection:

1. Build SKU set from seed/data source.
2. Run metadata contract audit.
3. Run media URL audit (`/uploads` vs `/static` expectations).
4. Run thumbnail/image-order audit for storefront assumptions.
5. Validate catalog scope mapping (`active` vs `paused`, kids/adult split behavior).
6. Record outcome in a per-collection status matrix.
7. If fixes are needed:
   - apply grouped mass fixes first (shared pattern),
   - then collection-specific edge cases,
   - keep docs updated with exact evidence and unresolved manual gates.

### A4. Guardrails

- Do not reopen already validated collections unless a new cross-collection systemic issue is proven.
- Treat environment mismatches as deployment/environment diagnostics first.
- Do not mix runtime/seed/code refactors with documentation-only status updates unless explicitly planned.
- Keep fixes isolated by concern (metadata/media/order/scope), avoiding mega-commits.

## Initial rollout method (Layer B)

1. Detect collections present in current normalized seed data.
2. Cross-check against active/paused catalog scope keys.
3. Assign one status per collection using the reusable buckets.
4. Split follow-up work into:
   - **mass fixes** (shared scripts/helpers),
   - **collection-specific fixes** (edge semantics),
   - **manual review gates** (visual/browser-only).

The first rollout snapshot is maintained in:
`docs/project/collection-technical-media-readiness-rollout.md`.

## Read-only automation artifact

Machine-readable audit is generated by:

- `python3 apps/backend/src/scripts/audit-collection-readiness.py`

Default output:

- `docs/project/collection-technical-media-readiness-audit.json`

This script is read-only: it reads baseline + scope config and writes the report artifact only.
