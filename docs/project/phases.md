# Phases

Этапы разработки. Источник: MASTER_PRD.md, архитектурный план.

---

## Phase 0 — Подготовка

- Фиксация архитектуры, модели данных, API, product rules, MVP scope в /docs.
- Решение по структуре репозитория (монорепо: apps/backend, apps/storefront; админка — часть backend).

**DoD:** Утверждены architecture.md, data-model.md, api.md, product-rules.md, mvp-scope.md.

---

## Phase 1 — Backend base

- Поднять Medusa, PostgreSQL.
- Расширить Product: product_type. Seed: категории, 8–12 тестовых товаров (все типы).
- Кастомные сущности и миграции: RoomSet, RoomSetItem, Lead, BespokeRequest, PaymentLink.
- REST: продукты с фильтром по product_type; CRUD Room Set (админ); создание Lead/BespokeRequest; создание/получение Payment Link.

**DoD:** API по документации работает; seed загружается; данные видны (через админ или прямой доступ к БД).

---

## Phase 2 — Admin

- Medusa Admin: разделы Room Sets, Leads, Bespoke Requests, Payment Links (списки, детали, смена статусов).
- Создание Payment Link из заказа/лида: ввод суммы, копирование ссылки, шаблон сообщения клиенту. Обновление статуса оплаты вручную.

**DoD:** Менеджер обрабатывает заявки и может отправить клиенту ссылку на оплату по шаблону из PRD.

---

## Phase 3 — Storefront: каталог и карточка

- Главная, каталог, категории, фильтры (цена, материал, стиль, цвет).
- Карточка товара: галерея, цена, размеры, материалы, срок изготовления, доставка, описание; CTA по product_type (см. product-rules.md).

**DoD:** Все три типа товаров отображаются корректно; в корзину можно добавить только STANDARD и выбранные CONFIGURABLE; BESPOKE не добавляется в корзину.

---

## Phase 4 — Storefront: корзина и checkout

- Корзина, checkout (адрес, доставка, контакты), создание заказа в Medusa.
- После создания заказа — выдача Payment Link (создание записи и отображение страницы «Оплатите по ссылке» + при необходимости отправка письма с ссылкой).

**DoD:** Поток «корзина → оформление → заказ → ссылка на оплату» работает; оплата на сайте картой не реализуется.

---

## Phase 5 — Storefront: Room Sets и Bespoke

- Разделы /rooms, /rooms/[slug]: визуал, описание, список мебели, цена «от», CTA «Купить комплект», «Адаптировать под мою комнату».
- «Купить комплект» — добавление в корзину только товаров с типом, допускающим корзину.
- «Адаптировать под мою комнату» → `/bespoke/request?room_set_id=...`; форма заявки → создание Lead и BespokeRequest.

**DoD:** Room Sets отображаются и ведут в корзину или в заявку; форма bespoke создаёт Lead + BespokeRequest; в админке видны новые заявки.

---

## Phase 6 — Интеграция оплаты и полировка (опционально в MVP)

- Подключение провайдера payment link (генерация URL). Webhook об успешной оплате → обновление статуса заказа и Payment Link (если включаем в MVP).
- Уведомления: заказ создан, ссылка на оплату, заявка принята (по объёму MVP).

**DoD:** Оплата по ссылке доводит заказ до «оплачен» при включении webhook; иначе — ручное обновление статусов достаточно для MVP.
