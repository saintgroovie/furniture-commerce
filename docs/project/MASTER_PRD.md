# MASTER PRD

## Платформа мебельного бренда (E-commerce + Bespoke)

---

# 1. Product Vision

Создать сайт мебельного бренда/производства, который совмещает:

* каталог мебели
* покупку стандартных товаров через корзину
* заказ мебели по индивидуальным размерам
* заказ мебельных проектов
* готовые решения комнат (Room Sets)

Сайт ориентирован на **рынок РФ**.

Проект — **гибрид e-commerce и lead generation**.

---

# 2. Основная логика продукта

Система поддерживает **два основных флоу**.

## Ecommerce flow

```
каталог
↓
карточка товара
↓
корзина
↓
checkout
↓
оплата
```

Используется для **стандартных товаров**.

---

## Bespoke flow

```
карточка товара
↓
кнопка "сделать по моим размерам"
↓
заявка
↓
расчёт менеджером
↓
payment link
↓
производство
```

Используется для **кастомных заказов**.

---

# 3. Сегменты пользователей

## Сегмент 1

Покупатель готовой мебели

Покупает:

* стол
* стул
* тумбу
* комод

Главная задача:

быстро купить мебель.

Использует **корзину**.

---

## Сегмент 2

Semi-custom покупатель

Хочет изменить:

* размер
* материал
* цвет

Использует:

* корзину
  или
* заявку на расчёт.

---

## Сегмент 3

Заказчик проекта

Заказывает:

* кухню
* гардеробную
* шкаф
* мебель под помещение

Использует **bespoke flow**.

---

# 4. Типы товаров

Каждый товар имеет поле:

```
product_type
```

---

## STANDARD

Можно купить сразу.

Примеры:

* стул
* тумба
* полка

CTA:

```
Добавить в корзину
```

---

## CONFIGURABLE

Есть варианты:

* материал
* цвет
* размер

Можно:

```
купить
или
отправить на расчёт
```

CTA:

```
Добавить в корзину
Сделать по моим размерам
```

---

## BESPOKE

Полностью кастомная мебель.

Примеры:

* кухня
* гардеробная
* шкаф в нишу

CTA:

```
Получить расчёт
```

---

# 9. Payment flow

В MVP используется **payment link**.

Администратор:

1 создаёт ссылку
2 указывает сумму
3 отправляет клиенту

---

```

```

# 13. UX требования

Карточка товара должна:

* показывать размеры
* показывать материалы
* показывать срок изготовления
* показывать условия доставки
* показывать возможность изменения

Это снимает тревожность клиента.

---

# 14. MVP ограничения

```

сложные CRM интеграции
```
