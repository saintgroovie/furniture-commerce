# Catalog editor

Woodright OS exposes native Medusa draft creation, title/subtitle/description updates, public product image upload, gallery ordering/removal and thumbnail selection, variant title/SKU/base RUB price/option assignment, additive values on product-scoped options, and server-gated publication or hiding. New products start as drafts. No catalogue data migration or seed is included.

Access follows the existing backend model: only the `god` role can use catalog editor APIs. Reads/writes verify the pinned backend component and database identity; mutations additionally require the configured origin and `WOODRIGHT_LIVE_WRITES=1`. Browser clients never receive native bearer tokens. Image uploads are limited to 8 MB JPG/PNG/WebP, checked by signature, sent to the native public file provider, then attached through a product update. Existing image IDs are retained. Detaching a photo does not delete its file, because other records may reference it.

The browser sends an opaque version of the complete native product response, including variant/price/image/option relations, before each mutation. The sole deployed workspace process serializes product writes and SKU checks; stale reads are rejected without replacing pending form content. This process-local guard is not a distributed lock for direct native Medusa clients or future replicas. Keep the single-runtime deployment contract. Native commerce workflows perform persistent mutations and own their transactions/compensation. No second database or browser persistence is introduced.

Updating RUB prices preserves the remaining native base-price entries, foreign currencies, quantity bounds and pricing rules. Existing inventory settings are not overwritten. Execution-bound photos cannot be removed through the general gallery. Option values use product-scoped additive links, never replacement of a shared global definition. A separate save applies each section; successful changes are reread from Medusa. A refresh failure after successful saving does not repeat the mutation. Unconfirmed native writes require rereading the object before retrying.

Validation includes policy/command tests, compiled authentication/CSRF/HTTP checks, and a bounded real-database drill using an explicitly identified hidden temporary draft. Back up and rehearse restore before the drill. Verify independent sign-in, exact uploaded bytes, prices and options; soft-delete the exact draft and delete only its own uploaded test files afterwards. Never publish the control product or alter an existing catalog item to test the editor.
